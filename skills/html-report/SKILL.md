# Skill: HTML Report

## Purpose

Generate a self-contained, single-file HTML report with a dark-themed design system. Reports are saved to the current session's files folder and opened automatically in the browser. This skill provides the full CSS design system and component library so agents can produce consistent, high-quality visual output without design decisions.

---

## When to Trigger

Invoke this skill if **any** of these are true:
- You completed a research task and want to present findings visually
- The user explicitly asks for an HTML report, visual summary, or "make it pretty"
- You produced structured data (comparisons, benchmarks, scores, rankings) that benefits from tables, badges, and colour coding
- A task summary has enough structure (3+ sections) to warrant navigation
- You are generating a weekly report, audit summary, or analysis with multiple dimensions

**Do NOT use when:**
- The output is a single paragraph or short answer — use plain text
- The user asked for markdown specifically
- The output is destined for another system (Jira, Confluence, Notion) — use that system's format

## How to Use

### Step 1 — Determine the session files path

```bash
# Get the current session ID and build the files path
SESSION_ID=$(ls -t ~/.copilot/session-state/ | head -1)
FILES_DIR="$HOME/.copilot/session-state/$SESSION_ID/files"
mkdir -p "$FILES_DIR"
```

### Step 2 — Choose a filename

Use kebab-case, descriptive names. Include the date if the report is periodic.

```
<topic>-report.html          # e.g. ai-benchmarks-report.html
<topic>-<date>.html           # e.g. weekly-learnings-2025-W29.html
<topic>-analysis.html         # e.g. auth-flow-analysis.html
```

### Step 3 — Assemble the HTML

Use the **Design System** and **Component Library** below. Every report follows this skeleton:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>REPORT_TITLE</title>
  <style>
    /* — Paste the full Design System CSS below — */
  </style>
</head>
<body>
  <aside class="sidebar">
    <div class="sidebar-header">
      <h2>SIDEBAR_TITLE</h2>
      <p class="subtitle">SUBTITLE_TEXT</p>
    </div>
    <nav>
      <a href="#section-1" class="nav-link active">Section 1</a>
      <a href="#section-2" class="nav-link">Section 2</a>
      <!-- ... more nav links ... -->
    </nav>
    <div class="sidebar-footer">
      <p>Generated by Copilot</p>
      <p class="date">GENERATION_DATE</p>
    </div>
  </aside>

  <main>
    <section id="section-1">
      <h1>Section 1 Title</h1>
      <!-- Components go here: cards, tables, callouts, etc. -->
    </section>

    <section id="section-2">
      <h1>Section 2 Title</h1>
      <!-- More content -->
    </section>
  </main>

  <script>
    /* — Paste the Sidebar Navigation JS below — */
  </script>
</body>
</html>
```

### Step 4 — Write the file and open it

```bash
# Write the HTML (use cat heredoc, printf, or Python — whatever is cleanest)
cat > "$FILES_DIR/my-report.html" << 'REPORT_EOF'
<!DOCTYPE html>
...full HTML here...
REPORT_EOF

# Open in default browser (macOS)
open "$FILES_DIR/my-report.html"
```

### Step 5 — Confirm to the user

After opening, print a short confirmation:

```
📊 Report saved to: ~/.copilot/session-state/<session-id>/files/<name>.html
🌐 Opened in browser.
```

## Sidebar Navigation JS

Paste this inside a `<script>` tag at the end of `<body>`.

```javascript
// Highlight active nav link on scroll
(function() {
  const sections = document.querySelectorAll('section[id]');
  const navLinks = document.querySelectorAll('.nav-link');

  function setActive() {
    let current = '';
    sections.forEach(function(section) {
      const top = section.offsetTop;
      if (window.scrollY >= top - 120) { current = section.getAttribute('id'); }
    });
    navLinks.forEach(function(link) {
      link.classList.remove('active');
      if (link.getAttribute('href') === '#' + current) {
        link.classList.add('active');
      }
    });
  }

  window.addEventListener('scroll', setActive);
  setActive();

  // Smooth scroll on click
  navLinks.forEach(function(link) {
    link.addEventListener('click', function(e) {
      e.preventDefault();
      var target = document.querySelector(this.getAttribute('href'));
      if (target) { target.scrollIntoView({ behavior: 'smooth', block: 'start' }); }
    });
  });
})();
```

## Output Contract

After generating and opening the report, the agent MUST:

1. **Save** the file to `~/.copilot/session-state/<session-id>/files/<name>.html`
2. **Open** it with `open <filepath>` (macOS)
3. **Confirm** to the user with:
   ```
   📊 Report saved to: ~/.copilot/session-state/<session-id>/files/<name>.html
   🌐 Opened in browser.
   ```
4. **Do NOT** ask the user for permission before generating — just generate and open it
5. The HTML file must be **fully self-contained** — no external CSS, JS, fonts, or images

## Tips for High-Quality Reports

1. **Lead with a stat row** — put 3–5 KPIs at the top so the reader gets the headline immediately
2. **Use badges in tables** — never leave status columns as plain text; always badge them
3. **One callout per section max** — callouts lose impact when overused
4. **Sidebar nav must match sections** — every `<section id="...">` needs a corresponding `<a href="#...">` in the nav
5. **Use card grids for comparisons** — side-by-side cards are easier to scan than long prose
6. **Score bars for quantitative data** — always prefer a visual bar over a plain number
7. **Date the report** — always include the generation date in the sidebar footer
